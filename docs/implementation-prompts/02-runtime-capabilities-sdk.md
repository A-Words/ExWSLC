## 实现要求

1. 完善 RuntimeCapabilities 和 RuntimeCapabilityService，区分 CLI 版本、运行时服务版本、项目实际引用的 SDK 包版本。当前 SdkVersion 来自 WslcService.GetVersion()，先核对其含义，不把服务版本冒充包版本。
2. 新版优先使用 wslc version --format json；旧版保留经过验证的回退。用已发布版本资料、相关命令／选项帮助与实际接口建立小型能力约定，表达支持、不支持、未能确认及原因。探测一次并复用，避免每轮库存刷新重复启动所有探测命令。
3. 能力至少供后续健康检查、网络连接／断开、文件复制、扩展构建、挂载／拉取策略／停止超时、system info、原生重启、事件流使用。只查询本任务需要的命令；不要为了发现能力创建容器、启动会话或运行有副作用的命令。
4. 未知或检测失败不等于整个 WSLC 不可用。保留原有基础能力；新功能需要明确支持证据才能启用，并提供可本地化的不可用原因。原生重启和事件流不能仅按 WSL 版本号认定可用。
5. 查询 Microsoft.WSL.Containers 实际发布版本并完成适用于本项目的 SDK 升级与必要适配。调研时 NuGet 列出的版本为 2.9.3 和 2.9.9，不能把运行时版本号直接填成包版本。重点核对安装 API 的 InstallOptions 等签名变化和缺失组件检测，保留用户主动安装流程。
6. 先在 docs 中写下简短的能力命名、语义、探测及回退约定，再实现；提供后续任务可以直接复用的接口示例。范围以当前需要为限，不搭建通用插件框架。
