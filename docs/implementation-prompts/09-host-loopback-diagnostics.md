## 实现要求

1. 在运行环境诊断区域增加“容器访问 Windows 本地服务”的说明与检查入口。上游引入了 host.wslc.internal；执行时核对当前 CLI／设置支持和实际配置域名，不假定所有会话、SDK 创建的会话或版本都支持。
2. 用户选择现有运行中的容器和明确的目标端口后，主动点击执行受限的 DNS／TCP 可达性检查。结果区分域名解析失败、目标连接失败、能力未启用、容器未运行和容器缺少诊断工具。
3. 复用或小范围扩展运行时诊断接口，命令参数以 ArgumentList 传递。探测使用固定程序参数；如果必须经过容器 shell，不能把未经校验的用户输入拼进去。
4. 检查有明确超时、取消和目标绑定，切换表单不会改变在途请求。仅检查用户指定的目标，不批量扫描端口，不安装容器工具、不修改 DNS／防火墙，也不自动启动已有容器。
5. 根据结果给出具体的下一步，例如核对本地服务监听端口、查看 WSLC 原生设置；不要把 DNS 成功等同于服务可访问，也不要让用户把服务无条件暴露到所有网卡。
6. 保持诊断结果临时、可复制且经过脱敏，不抓取或记录服务响应正文与凭据。本任务不实现 WSLC YAML 编辑器或端口转发管理。

## 本任务重点验证

自定义域名、未知／禁用能力、端口校验、容器停止或删除、DNS 成功但 TCP 失败、缺少工具、取消与超时、输入注入边界。真实检查只针对明确选择的本地测试服务和测试容器。
