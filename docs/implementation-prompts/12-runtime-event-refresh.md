## 入口可用后的实现要求

1. 先在 docs 中记录与 10 的刷新调度衔接、订阅生命周期和回退规则，再在 IContainerRuntime 后提供可取消的事件读取能力。
2. 仅消费实际支持的事件类型。用容器 create／start／stop／kill／destroy 等事件合并触发相关数据刷新，减少重复全量轮询；不要假定网络、卷、健康状态事件都已经可用。
3. 持续资源统计仍按需求采样，不能把生命周期事件当作 CPU／内存数据源。保留手动刷新和低频校准，以及旧版／订阅失败时的轮询回退。
4. 处理事件突发、重复、乱序、连接中断、服务重启、取消和重新订阅。重连后重新拉取库存以修复事件缺口；采用有界缓冲与退避，避免忙循环和无限积压。
5. 与最小化／恢复策略保持一致；不要让无用订阅无条件保持 VM 活动。退出时释放订阅和进程，不持久化事件清单或泄露事件中的敏感字段。
6. 事件用于触发状态更新，最终库存仍以运行时查询为准，不能把有限事件历史当成完整审计日志。
